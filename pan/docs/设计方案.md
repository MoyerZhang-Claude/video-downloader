# 网盘分享链接解析下载器 —— 设计方案（草案 v0.1）

> 目标：一个 Windows 桌面软件，粘贴网盘分享链接（或整段分享文案）→ 自动识别平台 → 解析出文件列表 → 选择文件 → 直接下载到本地。
> 原则：**功能、性能优先，界面朴素够用**。只使用你自己的账号和它应得的权益（不搞共享会员账号池、不破解平台限速）。

---

## 1. 2026-10-22 实测结论（用 `test-w.txt` 里的链接，未登录）

| 平台 | 解析文件列表 | 拿真实下载地址 | 是否必须转存 | 备注 |
|---|---|---|---|---|
| 百度网盘 | ✅ 匿名可用（`share/verify` → `share/list`） | ❌ 需登录（BDUSS） | 否，有 `api/sharedownload` 直取接口 | 速度取决于登录账号的会员等级 |
| 夸克网盘 | ✅ 匿名可用（`sharepage/token` → `sharepage/detail`） | ❌ 需登录（Cookie） | **是**，官方只允许下载自己网盘里的文件 | 网页版有大文件限制，需模拟 PC 客户端 |
| 123云盘 | ✅ 匿名可用（`www.123pan.cn/b/api/share/get`） | ❌ 需登录（匿名返回 5112“需要注册登录或付费后下载”） | 否，有 `share/download/info` 直取接口 | 新域名 `xxx.share.123pan.cn/123pan/...` 也能识别 |
| Mega | ✅ 匿名可用 | ✅ 匿名可用 | 否 | 文件是端到端加密的，下载后要本地 AES 解密；匿名有流量配额 |

结论：**“识别 + 列表”四家都不用登录；“下载”除 Mega 外都要登录你自己的账号。**

## 2. 技术选型（推荐）

| 层 | 选择 | 理由 |
|---|---|---|
| 后端/核心 | **Go** | 并发下载（goroutine）性能好、内存低；电脑上编译成单个 exe，安卓上编译成 .so 库，**同一份核心代码两边复用** |
| 界面 | **Wails v3 + Vue 3** | 电脑上用 Windows 自带的 WebView2（本机已装 v155），安卓上用系统 WebView，**同一份界面代码两边复用**；Wails v3 已进入 beta，API 已稳定，安卓支持为实验阶段 |
| 数据存储 | **JSON 文件（原子写入）** | 保存任务、进度、设置；先写临时文件再改名，断电也不会损坏。任务量很大时再换 SQLite（modernc 纯 Go 版） |
| 账号凭据 | 电脑：**Windows DPAPI 加密**；安卓：**Android Keystore 加密** | Cookie/Token 只存在你自己的设备上 |

本机现状：Node 24 ✅、Python 3.13 ✅、Git ✅、WebView2 ✅；Go 需要安装。

为什么不用 Python：Python 做安卓应用（Kivy / BeeWare / Flet / PySide6 安卓版）打包麻烦、加密等原生库难装、下载性能和耗电都更差，**安卓兼容性反而是几种方案里最弱的**。
另一个可选方案是 Rust + Tauri v2（官方正式支持安卓），但 Rust 开发和编译都更慢；Go 核心跑在安卓上已有大量成熟先例（sing-box、Clash for Android、AList 安卓版的核心都是 Go），所以选 Go。

## 3. 整体架构

```
┌──────────────────────── 界面（Vue，电脑/安卓共用） ─────────┐
│ 粘贴/剪贴板监听 │ 文件树勾选 │ 下载队列 │ 账号管理 │ 设置   │
└──────────────┬──────────────────────────────────────────────┘
               │ 外壳层：电脑 = Wails v3 窗口；安卓 = Wails v3 安卓壳（或自写 Kotlin 壳）
               │ 外壳只负责“转发命令 + 推送事件”，不含任何业务逻辑
┌──────────────┴──────────── Go 核心（不依赖任何界面） ───────┐
│ linkparse  链接识别：从任意文本中提取链接 + 提取码          │
│ provider   平台适配器：baidu / quark / pan123 / mega（插件式）│
│ account    账号：扫码登录 / 粘贴 Cookie，DPAPI 加密存储     │
│ queue      任务队列：状态机、并发控制、失败重试、临时转存清理 │
│ downloader 下载引擎：多连接分段、断点续传、限速、链接刷新    │
│ stats      速度统计：实时速度、平均速度、剩余时间            │
│ store      SQLite 持久化                                    │
└─────────────────────────────────────────────────────────────┘
```

### 3.1 平台适配器接口（每个网盘实现一份，新增平台只加一个目录）

```go
type Provider interface {
    ID() string                                       // "baidu" / "quark" / "pan123" / "mega"
    Match(text string) []ShareLink                    // 从文本里找出属于本平台的链接
    Open(ctx, link ShareLink, pwd string) (*Share, error)   // 校验提取码，拿到分享会话
    List(ctx, share *Share, dirID string) ([]Entry, error)  // 列目录（支持子文件夹）
    Resolve(ctx, share *Share, e Entry, acct *Account) (*Source, error) // 拿真实下载地址（可能内部做临时转存）
    Cleanup(ctx, acct *Account, token CleanupToken) error   // 删除临时转存的文件
}

type Source struct {
    URL      string
    Headers  http.Header      // 各家要求的 UA / Cookie / Referer
    Size     int64
    MaxConns int              // 该平台/账号建议的并发连接数
    Expires  time.Time        // 链接过期时间
    Refresh  func(ctx) (*Source, error) // 链接过期后重新获取（下载不中断）
    Decrypt  func(offset int64) cipher.Stream // 只有 Mega 用：按偏移量解密
    Checksum *Checksum        // 可选：下载完校验 MD5
}
```

## 4. 各平台实现要点

### 4.1 链接识别（从整段分享文案里提取）
- 百度：`pan.baidu.com/s/1xxxx`、`pan.baidu.com/share/init?surl=xxxx`
- 夸克：`pan.quark.cn/s/xxxx`（文案里的 `/~xxxx~:/` 是 App 口令，忽略）
- 123：`123pan.com|123pan.cn|123684.com|123865.com|123912.com|123592.com/s/xxxx`，以及 `数字.share.123pan.cn/123pan/xxxx`
- Mega：`mega.nz/file/ID#KEY`、`mega.nz/folder/ID#KEY`（含子目录形式）、旧格式 `#!ID!KEY`、`#F!ID!KEY`
- 一次粘贴多条链接 → 批量识别。
- **提取码**：链接里带了 `?pwd=xxxx` 就直接用；没带而分享又需要 → **弹窗让你手动输入**，输入后再解析。提取码错了提示重输。

### 4.2 百度网盘
1. `share/verify`（提交提取码）→ 得到 `randsk`（作为 Cookie `BDCLND`）
2. `share/list` 列文件（子目录用 `dir` 参数），`share/tplconfig` 拿 `sign`/`timestamp`
3. **免转存直取**：`api/sharedownload`（`product=share`、`extra={"sekey": randsk}`、`fid_list`、`primaryid`、`uk`）→ 得到 dlink → 带你的 BDUSS 请求一次拿到最终 CDN 地址
4. 如果直取失败（接口改版 / 要求验证码 / 大文件限制）→ **自动回退到“临时转存”**（见第 5 节）
5. 下载请求需带百度要求的特殊 User-Agent；**速度 = 你账号的会员速度**。SVIP 用多连接跑满；普通账号会被百度服务端限速，并且默认只开少量连接，避免账号被风控。
6. 登录：手机百度网盘 App **扫码登录**（首选），或粘贴 Cookie（BDUSS/STOKEN）。
7. 遇到验证码：把验证码图片显示给你，你输入后继续（软件不会自动破解验证码）。

**实测结论（2026-10-22，M3）**
- 扫码登录：`passport.baidu.com/v2/api/getqrcode` → 轮询 `/channel/unicast`（长轮询约 30 秒；`channel_v.status` 1 = 已扫码、0 + `v` = 已确认）
  → `/v3/login/main/qrbdusslogin?bduss=<v>` 换正式 cookie（**返回的是单引号 JS 对象，不是 JSON**）→ 访问 `/v3/login/api/auth/?return_type=5` 拿网盘域名的 STOKEN。
- 会员：`loginStatus` 的 `vip_type` 编号会变（SVIP 返回 21），以 `/rest/2.0/membership/user?method=query` 的 `current_product.detail_cluster` 和 `product_infos[].end_time` 为准。
- 下载：`/api/sharedownload` 必须用**网页版写法**：先打开分享页（拿 BAIDUID 等 cookie）、带 `clienttype=0` 和 `bdstoken`；否则返回 9019（need verify）。
- 真实下载地址（`*.baidupcs.com`）：**单次 Range 请求最多 4MB**（8MB 就 403），且 **UA 必须和取地址时一致**；支持任意位置分段。
  引擎增加了 `MaxChunk`（每条连接按 4MB 连续请求），SVIP 单连接约 6～8 MB/s，8 连接跑满 100M 宽带。
- 未覆盖：别人的分享（测试链接都是自己的分享）、大量下载后是否触发验证码，留待实际使用中观察。

### 4.3 夸克网盘
1. `sharepage/token`（含提取码）→ `stoken`；`sharepage/detail` 列文件（带 `share_fid_token`）
2. 官方不允许直接下载别人的分享 → 走**临时转存**：`sharepage/save` 存到你网盘里的临时目录 → 轮询 `task` 等完成
3. `file/download` 拿下载地址（模拟 PC 客户端参数与 UA，绕开“网页版大文件需用客户端”的限制）
4. 下载完成后自动删除临时文件
5. 登录：夸克 App 扫码登录（首选）或粘贴 Cookie。
6. 注意：临时转存会暂时占用你网盘的空间（测试链接的文件约 453MB）。

**实测结论（2026-10-22，M4）**
- 扫码登录：`uop.quark.cn/cas/ajax/getTokenForQrcodeLogin` → 二维码内容 `https://su.quark.cn/4_eMHBJ?token=…&client_id=532&ssb=weblogin&…`
  → 每 2 秒轮询 `getServiceTicketByQrcodeToken`（2000000 = 已确认并返回 service_ticket；50004001 = 未确认；50004002 = 令牌不存在/过期）
  → `pan.quark.cn/account/info?st=…&lw=scan` 下发 `__pus` 等 cookie。
- **关键：`__puus` 不是扫码时给的**，而是调用 `drive-pc.quark.cn` 的接口时由 Set-Cookie 下发并定期更换。网盘接口不校验它，
  但**下载服务器必须带上它**（缺了返回 412/403）。所以每次取下载地址前先调一次会员接口刷新 cookie 并存回账号；引擎把 412 视为“需要刷新地址”。
- 下载地址：`/file/download` 要用电脑客户端 UA 申请（网页身份对大文件返回 23018）；下载服务器不校验 UA，支持分段，会员实测跑满 100M 宽带。
- 转存自己的分享返回 41017（用户禁止转存自己的分享）：此时直接下载原文件，不转存、也绝不删除原文件。
- 转存时文件令牌（`share_fid_token`）必须和**同一次、登录状态下**取得的分享令牌（stoken）配套，并且 `pdir_fid` 要填文件在分享里所在的文件夹；
  混用解析时（未登录）拿到的旧令牌会返回 41020（转存文件 token 校验异常）。所以转存前会用登录 cookie 重新取 stoken、重新列一次文件夹拿新令牌。
- 实测（别人的分享，子文件夹里的 303MB 文件）：转存 → 下载 27 秒（12.4 MB/s）→ 自动删除，临时文件夹清空，APK 内 5058 个文件 CRC 全部通过。
- 删除临时文件用的是普通删除（进夸克回收站）；临时文件夹本身会保留（空文件夹）。

### 4.4 123云盘
1. `share/get` 列文件（`shareKey` + `SharePwd`）
2. `share/download/info` 直接拿下载地址（**无需转存**，但需登录）；返回的地址可能是一层跳转，需解出最终 CDN 地址
3. 部分接口要求请求签名（时间戳 + CRC32），按网页端规则实现
4. 登录：账号密码登录或扫码登录 → 得到 Bearer Token
5. 实测结论（2026-10-22）：
   - 登录只做**扫码**（123云盘 App / 微信）+ 手动粘贴 authorToken。网页的账号密码登录要在本地加密密码并过阿里云滑块验证，软件里不可靠。
   - 扫码结果接口：`code 0` 时看 `loginStatus`（0 未扫 / 1 已扫 / 2 取消 / 3 确认 / 4 过期）；**`code 200` 表示已确认，data 里直接带 token**，扫码平台在 `login_type`（7 = App，4 = 微信，微信需再换一次 wx_code 登录）。
   - 下载他人分享消耗的是**分享者的「提取流量包」**，不足时返回 5113；免费用户每月另有 10GB“网盘内下载流量”。
   - 分享里的文件属于自己时（`S3KeyFlag` 前缀 = 自己的 UID），改用 `/file/download_info` 下载自己的文件，不消耗分享流量。
   - 123 的 `Etag` 就是文件 MD5，下载后据此校验。
   - 分享者流量不足时的兜底：转存到自己网盘再下载（保存接口为 `/restful/goapi/v1/file/copy/save` + `/copy/save/get?taskID=`，参数待抓包确认），和夸克的临时转存一起在 M4 实现。

### 4.5 Mega
1. 链接 `#` 后面是解密密钥，**密钥只在本地使用，不会发给任何服务器**
2. API `a:g` 拿下载地址和加密的文件名；文件夹用 `a:f` 列出所有节点，再用文件夹密钥解出每个文件的密钥
3. 文件内容是 **AES-128-CTR** 加密：CTR 模式可以从任意位置解密，所以**多连接分段下载完全可行**——每段按偏移量算出计数器，边下边解密直接写盘
4. 匿名有流量配额（超出会报 509，需要等待一段时间）；后期可加 Mega 账号登录提升配额

## 5. “免转存下载”方案（重点）

不同平台情况不同，所以分两类处理，**对你来说操作完全一样：粘贴 → 选文件 → 下载**。

| 类型 | 平台 | 做法 |
|---|---|---|
| 真·免转存 | 百度（优先）、123、Mega | 平台本身有“分享文件直接下载”的接口，直接拿下载地址，网盘里不留任何东西 |
| 透明临时转存 | 夸克、百度（回退） | 软件自动：① 转存到你网盘里的专用临时文件夹 `/_解析临时/任务ID/` → ② 取下载地址并下载 → ③ 下载完成自动删除（可选同时清空回收站中的这些文件） |

临时转存的可靠性设计：
- 每次转存都先在本地数据库记一笔“待清理”，即使软件崩溃/断电，**下次启动会自动把残留的临时文件删掉**。
- 下载过程中链接过期时，用临时文件重新取地址，所以必须等下载完成才删除。
- 转存前检查网盘剩余空间，空间不够直接提示，不会转存一半。
- 转存是服务端秒级完成的（不走你的带宽），不会额外拖慢速度。

## 6. 下载引擎（性能核心）

| 功能 | 实现方式 |
|---|---|
| 多连接分段下载 | 用 HTTP Range 把文件切成多段并行下载；某条连接完成后，自动“拆分”剩余最多的那一段接着下（类似 IDM 的动态分段），避免最后只剩一条慢连接拖尾 |
| 写盘性能 | 预先分配文件大小，每条连接带 1~4MB 缓冲，`WriteAt` 直接写到对应位置，不合并临时分片 |
| 暂停/继续 | 暂停 = 取消所有连接并保存各段进度；继续 = 从各段断点接着下 |
| 断点续传 | 每 1~2 秒把各段进度写入数据库；软件关闭/崩溃/断网后重新打开可继续 |
| 失败重试 | 分段级：网络错误自动重试（指数退避 + 随机抖动）；任务级：可设置最大重试次数，也可手动“重试” |
| 错误分类 | 网络抖动 → 自动重试；链接过期（403/410）→ 自动刷新地址后继续；配额不足/需登录/文件被删 → 停下并提示原因 |
| 速度统计 | 每条连接原子计数，每 0.5 秒采样，平滑后显示：实时速度、平均速度、剩余时间、已用时间；以及全局总速度 |
| 限速 | 可选全局限速（令牌桶，所有连接共享） |
| 并发控制 | 同时下载任务数（默认 3）、每任务连接数（按平台/会员等级给默认值，可手动改） |
| 完整性校验 | 平台提供 MD5 的（如 123 的 Etag）下载完可选校验；Mega 可做 MAC 校验 |

任务状态：`等待中 → 解析中 → (转存中) → 下载中 ⇄ 已暂停 → 校验中 → (清理中) → 已完成`，任一环节出错 → `失败（可重试）`

## 7. 界面（朴素版）

1. **主页**：一个大输入框（粘贴链接/整段文案）+「解析」按钮；可选开启“剪贴板监听”，复制链接自动弹出
2. **解析结果**：文件树（支持文件夹）、勾选、显示大小、选择保存目录 →「加入下载」
3. **下载队列**：每行显示文件名、平台、进度条、速度、剩余时间、状态；按钮：暂停/继续/重试/删除/打开文件夹；顶部：全部暂停/全部开始、总速度
4. **账号**：每个平台显示登录状态、会员等级；扫码登录 / 粘贴 Cookie / 退出
5. **设置**：默认下载目录、同时任务数、每任务连接数、全局限速、重试次数、代理、临时转存目录名、是否自动清理回收站

## 9. 开发路线（每一步都能单独运行验证）

| 阶段 | 内容 | 需要你做的 |
|---|---|---|
| M0 ✅ | 搭项目骨架 + **下载引擎**（多连接、暂停/继续、续传、重试、速度统计）+ 队列界面，用普通直链测试 | 同意安装 Go |
| M1 ✅ | 链接识别 + **Mega**（不用登录，正好端到端验证引擎和解密）；顺带完成百度/夸克/123 的提取码校验和文件列表（不用登录的部分） | 无 |

## 10. 安卓版规划（M6，电脑版稳定后再做）

**复用**：Go 核心（链接识别、四个平台适配器、下载引擎、队列、数据库）和 Vue 界面全部复用，安卓上只需要补“安卓特有”的部分：

| 安卓特有问题 | 方案 |
|---|---|
| 锁屏/切后台后下载会被系统杀掉 | 用**前台服务**（通知栏常驻“正在下载 xx%”），这是安卓下载类应用的标准做法 |
| 存储权限（Android 10+ 分区存储） | 先下载到应用自己的目录（支持多线程随机写），完成后移动到系统“下载”文件夹；或申请“所有文件访问权限”（自用 APK 可以） |
| 手机上没法扫自己屏幕上的二维码 | 登录方式增加“**应用内网页登录**”：在软件里打开网盘官方登录页，你正常登录后软件读取 Cookie。电脑版也同时支持这种方式 |
| 界面尺寸 | Vue 界面做成响应式，窄屏自动切换成手机布局 |
| 外壳 | 优先用 Wails v3 的安卓支持；如果到时候它还不够稳定，就自写一个很薄的 Kotlin 壳加载同样的 Go 核心和界面（核心与界面不用改） |

为保证将来能顺利移植，从第一天起就遵守三条规则：
1. Go 核心**不能引用任何界面/Windows 专属代码**，Windows 专属的东西（DPAPI、剪贴板）放在可替换的小接口后面。
2. 核心对外只暴露“命令 + 事件”的接口，数据都用 JSON，任何外壳都能对接。
3. 所有文件路径、下载目录、数据目录由外壳传入，核心不写死路径。

## 11. 风险与说明

- **接口会变**：这些都是网页/客户端的非公开接口，平台改版就可能失效。每个平台单独一个适配器，坏了只修那一个，不影响其他。
- **风控**：短时间大量解析/转存可能触发验证码或临时封禁，软件会控制请求频率并在需要时请你输入验证码。
- **速度上限 = 你账号的权益**：会员跑满会员速度；非会员受平台服务端限速，软件不做破解。
- **凭据安全**：Cookie/Token 只加密保存在本机，不上传任何地方。
