### 行为变化与取舍

- 123 转存成功而后续解析失败时，临时文件会一直保留到任务重试成功或任务被删除；这是为可恢复性所作的有意改变，会暂占网盘空间。
- 原始错误仍原样返回，未修改错误分类、自动重试次数或登录提示。
- 仅含 Persist 的 Source 不可当成可下载地址使用；调用者必须先处理 error。队列已有实现遵守该约定。
- 目前仍使用原有的 250ms 合并写盘，未消除“转存成功到队列收到并保存 ID”之间的强制崩溃窗口。新增重启测试验证的是正常关闭落盘，不等于 kill/断电测试。

### 可复用的验证命令

在项目根目录的 PowerShell 中：

```powershell
$auditTmp = Join-Path (Get-Location) 'bin\codex-audit-temp'
New-Item -ItemType Directory -Force -Path $auditTmp | Out-Null
$env:TEMP = $auditTmp
$env:TMP = $auditTmp
$env:GOTMPDIR = $auditTmp
$env:GOPROXY = 'off' # 本机依赖已缓存；换机器首次开发应正常安装依赖
$env:GOTOOLCHAIN = 'local'
go test ./... -count=1 -timeout=120s
Push-Location frontend
try {
    npm run test:share-dialog
    npm run build -- --outDir ../bin/codex-handoff/2026-10-22/frontend-check
} finally {
    Pop-Location
}
```

若在限制回环网络的沙箱中执行，需要为这些本地测试授权网络访问；否则会出现 socket 权限错误，不能用该结果判断平台适配器失效。
