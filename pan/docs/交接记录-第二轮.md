## 行为变化与限制

### 123 并发转存

原实现按 Etag 在共享临时目录中选择最大文件 ID。新增测试在修改前源码上复现：两个并发任务都取得 ID 100，或误认领已有 ID 1000。

现在同一个 Resolver 的转存操作串行，且排除转存前已存在的所有文件 ID。如果平台去重导致没有新增可独立清理的文件，任务报错提示等待已有下载结束后重试，不共享其他任务文件的删除权限。测试覆盖了这两种行为；**本轮没有用真实 123 账号触发流量不足回退，平台去重的真实细节仍待验证**。

该限制只在同一个 Resolver 内生效。多个独立进程使用同一网盘临时目录的协调尚未实现；桌面同数据目录已有单实例限制，但不同数据目录/开发工具仍可能绕过它。

### 清理记录恢复

原实现存在两个窗口：重试开始即清空 cleanups，首次删除任务时也只有请求失败才记录 cleanups。中途退出可能让任务和清理记录一起消失，启动时的 Sweep 还会把正在清理的 ID 当成无引用文件。

现在首次删除任务就记录清理意图；请求完成前，记录一直参与任务快照和 Sweep 引用。完成批次时，仅移除成功项并更新失败项，保留后来追加的项。已有批次进行中时追加的清理，可能需要等下一次周期重试（原周期 10 分钟）。

这次测试验证了**请求未完成时已写入磁盘的快照**和正常重启恢复，没有宣称断电绝对安全。仍存在的窗口：

- 转存接口已接受操作但还没返回文件 ID；等待/列目录失败时可能还不知道需清理哪个文件。
- 文件 ID 目前在 Resolver 返回后才交给队列，任务快照仍是 250ms 合并写盘；尚未增加“拿到 ID 立即同步落盘”的机制。
- 123 清理接口重复执行是否总能幂等成功，尚未做真实平台异常中断验证。

## 实测工具使用与隔离

```powershell
go build -o bin/pandl-check.exe ./cmd/pandl-check
# 默认只列有限目录，不取下载地址，也不转存
.\bin\pandl-check.exe -input test-w.txt -provider baidu -number 3
# 使用已登录账号的隔离副本，按上限读取一个最小文件
.\bin\pandl-check.exe -input test-w.txt -provider quark -number 3 -app-login -download
```

- 默认不读取桌面账号；`-app-login` 才复制加密的 accounts.dat 到临时目录。原账号文件未修改，也未发起新扫码。
- 不启动 Core/Queue，不加载用户任务，不进行启动扫描或历史残留清理。
- 每条分享最多读取 6 个子目录、3 层；选择发现的最小文件。单条分享有 90 秒截止时间。
- `-download` 后，小于等于 2 MiB 的文件走实际下载引擎并在有校验值时校验；大文件最多读取 64 KiB 应用层数据。不会执行下载文件。
- 仅对本次 Resolver 返回的 Persist 调用 Finish；清理有单独 30 秒截止时间。清理失败则保留本次隔离目录、加密账号副本和恢复记录，输出目录位置，不扫描其他文件。
- 输出 JSON 仅含平台、序号、大小、阶段结果、校验方式及经过地址遮盖的错误。失败返回非零退出码。
- 本轮所有夸克测试均报告 `cleaned=true`，相应临时恢复目录自动删除；云端空的专用临时目录按原设计保留。
